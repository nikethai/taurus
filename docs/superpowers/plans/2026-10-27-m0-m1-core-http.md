# M0 + M1: Workspace and Core HTTP Engine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 2022 Tauri/React prototype with a Rust workspace whose `taurus-core` engine downloads HTTP(S) files in parallel segments, survives a hard kill, and resumes byte-perfect, driven from a `taurus` CLI.

**Architecture:** `taurus-core` is a UI-free library. An `Engine` handle (cheap clone) talks to a background actor task over an mpsc channel; each running job is a tokio task with one worker per segment writing at its own offset into `<name>.tapa`. Progress is committed to SQLite only after the bytes are fsynced. `taurus-cli` is a thin front end; `taurus-testkit` is a local fake HTTP server used by all tests.

**Tech Stack:** Rust 2024 edition, tokio 1.54, reqwest 0.13 (`stream` feature), rusqlite 0.41 (`bundled`), thiserror 2, clap 4.6, axum 0.8 (tests only), tokio-util 0.7 (CancellationToken), sha2 0.11, directories 6, fastrand 2.

**Spec:** `docs/superpowers/specs/2026-10-27-taurus-v2-design.md` (sections 2, 5, 6.1–6.3, 7 "HTTP", 8, 9 rows M0–M1).

## Global Constraints

- License: GPL-3.0-or-later for every crate (`license = "GPL-3.0-or-later"`).
- Edition 2024, `rust-version = "1.85"`; CI must pass `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` on ubuntu-latest, macos-latest, windows-latest.
- Partial file extension is exactly `.tapa` (`<final name>.tapa`).
- One stable User-Agent: `Taurus/<CARGO_PKG_VERSION> (+https://github.com/nikethai/taurus)`. No random user agents.
- Probe with `GET` + `Range: bytes=0-0`, never HEAD. Always send `Accept-Encoding: identity`.
- Segments: default max 16 connections, minimum segment 1 MiB (1_048_576 bytes); files under 1 MiB use one segment.
- Progress events: at most 4 per second per job.
- Durability: recorded segment progress must never exceed bytes fsynced to disk; commit cadence ~1 s and on pause.
- Never overwrite an existing file: pick `name (1).ext`, `name (2).ext`, ...
- Product name is **Hyades**; crate names, binary (`taurus`) and data dirs keep the codename `taurus` until the M7 packaging plan renames user-facing pieces. No user-facing name strings in core.
- No tests touch the real internet. All HTTP tests use `taurus-testkit`.

## Review Focus

1. A server that answers the probe with 206 but ignores `Range` on later requests (returns 200 + full body) must not corrupt the file → job falls back to a single stream from offset 0. Test: Task 7 `ignored_range_falls_back_to_single_stream`.
2. A connection that drops mid-segment must resume that segment from its durable offset, not restart the job → final hash matches. Test: Task 7 `dropped_connection_retries_segment`.
3. The file changing on the server between sessions (new ETag) must restart from zero instead of stitching two versions together. Test: Task 8 `changed_etag_restarts_from_zero`.
4. Two downloads of the same file name into one folder, or a file that already exists, must never overwrite → `name (1).ext`. Test: Task 8 `same_name_twice_gets_suffix`.
5. A destination folder that does not exist (unplugged drive) must fail clearly with `FolderUnavailable`, not panic or create random paths. Test: Task 8 `missing_dest_dir_fails_with_folder_unavailable`.

`run_job` algorithm (decisions the implementer cannot infer):
1. Load `JobRecord`. If it has no segments: use stored probe fields (`total`, `resumable`) to `plan_segments(total, connections)` when `resumable && total.is_some()`, else one segment `[0, u64::MAX)` with `resumable=false`; `replace_segments`.
2. Open/create `<dest_dir>/<file_name>.tapa`. Each worker opens its own handle, seeks to `cursor()`, writes chunks, stops at the segment's current `end` (an `Arc<AtomicU64>` the stealer may lower; truncate the last chunk).
3. Worker requests `Range: bytes=<cursor>-<end-1>` (omit for non-resumable). If a ranged request returns 200 while `cursor > 0` or segment count > 1 → cancel all workers, set `resumable=false`, truncate `.tapa` to 0, restart as one non-resumable segment.
4. Every 1 s or 4 MiB per worker: `sync_data()`, then report the durable `done` to the job loop; the job loop calls `store.commit_progress` with all segments. On cancel: workers stop, sync, final commit, state Paused.
5. When a worker finishes, the job loop calls `plan::steal`; if `Some((i, split))`, lower segment `i`'s end to `split`, append `[split, old_end)` and start a worker for it (`replace_segments` then continue).
6. Per-segment errors: transient kinds retry with `backoff_delay(attempt)` up to `MAX_SEGMENT_ATTEMPTS`, resuming from the durable cursor; non-transient or exhausted → cancel all, state Failed with kind+detail.
7. Finish: verify `.tapa` length == `total` (when known; else accept), `sync_all`, rename to `unique_path`-checked final name (retry rename 5× with 200 ms sleep on `PermissionDenied`), state Completed. A 0-byte file is created empty and completes immediately.

```rust
pub struct EngineConfig { pub data_dir: std::path::PathBuf } // DB at data_dir/taurus.db
pub struct AddRequest { pub url: String, pub dest_dir: std::path::PathBuf, pub file_name: Option<String>, pub connections: Option<u32> }
#[derive(Clone, Debug, serde::Serialize)]
pub struct JobView { pub id: JobId, pub url: String, pub file_name: String, pub dest_dir: std::path::PathBuf,
                     pub state: JobState, pub total: Option<u64>, pub downloaded: u64, pub speed_bps: u64,
                     pub resumable: bool, pub error: Option<(ErrorKind, String)> }
#[derive(Clone, Debug, serde::Serialize)]
pub enum Event { JobAdded(JobView), JobUpdated(JobView), Progress { id: JobId, downloaded: u64, total: Option<u64>, speed_bps: u64 }, JobRemoved(JobId) }
#[derive(Clone)]
pub struct Engine { /* mpsc::Sender<Command>, broadcast::Sender<Event>, Arc<RwLock<HashMap<JobId, JobView>>> */ }
impl Engine {
    pub async fn open(config: EngineConfig) -> Result<Engine, CoreError>; // restores jobs; Downloading -> Paused on open
    pub async fn add(&self, req: AddRequest) -> Result<JobId, CoreError>; // probes, reserves name, starts immediately
    pub async fn pause(&self, id: JobId) -> Result<(), CoreError>;
    pub async fn resume(&self, id: JobId) -> Result<(), CoreError>;
    pub async fn remove(&self, id: JobId, delete_files: bool) -> Result<(), CoreError>;
    pub fn snapshot(&self) -> Vec<JobView>;
    pub fn subscribe(&self) -> tokio::sync::broadcast::Receiver<Event>;
    pub async fn wait(&self, id: JobId) -> JobState; // resolves on Completed | Paused | Failed
    pub async fn shutdown(&self) -> Result<(), CoreError>; // pauses all running jobs, flushes
}
```
