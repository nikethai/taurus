# M7 — Packaging, Updates, Translations and v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Hyades 1.0: installers for Windows, macOS and Linux built by a release workflow, signed update manifests with an in-app updater, a translation catalog with a pseudo-locale, the items M6b deferred, a visual pass against the design canvas, and the v1.0.0 tag.

**Architecture:**
- The engine gains `taurus_core::update`. It fetches a minisign-signed `latest.json` from the GitHub release and offers only a newer version. It downloads the platform's asset and checks its size and SHA-256 against the signed manifest.
- The desktop app decides how this install can update itself:
  - Windows NSIS installs run the new installer in passive mode;
  - the macOS `.app` swaps its bundle;
  - a Linux AppImage replaces its file;
  - deb, rpm and development builds only say a new version is out.
- Translations are gettext catalogs bundled into the binary by `slint-build`. Text the OS shows outside the window moves into a Slint global, so it uses the same catalog.
- A new `xtask` crate holds the tooling: catalog extraction, the pseudo-locale, icon generation, the release manifest and its signature.
- Packaging uses cargo-packager for NSIS, `.app`, deb and AppImage, and cargo-generate-rpm for rpm. A tag-triggered workflow builds every target on native runners and publishes a draft release.

**Tech Stack:**
- Rust 1.89 for the workspace; 1.92 for the desktop app and `xtask`.
- Slint 1.18: bundled translations and `@tr`; slint-tr-extractor 1.18.1.
- Signing: minisign-verify 0.3 in the app, minisign 0.10 in the tools and tests; semver 1.
- Packaging: cargo-packager 0.11.8 (CLI), cargo-generate-rpm 0.21, winresource 0.1.
- Icons: png 0.18, ico 0.6, icns 0.5.
- CI: GitHub Actions with arm64 runners `ubuntu-22.04-arm` and `windows-11-arm`.

**Spec:** `docs/superpowers/specs/2026-10-27-taurus-v2-design.md` — §1 (one installer per OS, x64 and arm64), §2 (packaging and auto-update), §7 i18n (`@tr`, pseudo-locale), §9 (macOS signing risk), §10 milestone M7. Earlier plans in `docs/superpowers/plans/` set the conventions this one keeps.

**Design reference:** `docs/design/canvas/` — board sources and screenshots, light and dark. See its README.

**Branch:** `m7`. Open the PR against `main` when Task 13 reaches its tag step.

## Decisions taken for you

These are made so the plan can be decisive. The user can overturn any of them before Task 1 starts. If Claude Code is told of a change, it applies it throughout the plan.

- **D1 · Names.**
  - The product name is **Hyades** everywhere a person reads it.
  - The desktop binary is `hyades` (`hyades.exe` on Windows, inside `Hyades.app` on macOS). Start-menu entries, shortcuts, the window and the installer all read "Hyades". The CLI binary is `hyades-cli`.
  - The bundle identifier is `dev.nikethai.hyades`.
  - Crate names stay `taurus-*` (codename).
- **D2 · Data folder unchanged.**
  - These keep their codename names: `directories::ProjectDirs::from("dev", "nikethai", "taurus")`, the `taurus.db` and `taurus.lock` files, and the keychain service `dev.nikethai.taurus`.
  - Moving them would mean migrating the database, the tool installs, librqbit's fastresume state and the keychain entries, for a name few people ever see.
  - `HYADES_DATA_DIR` becomes the documented override. `TAURUS_DATA_DIR` is still read when `HYADES_DATA_DIR` is unset.
- **D3 · Installers contain the app only.** The CLI ships as separate archives (`hyades-cli-<version>-<target>.tar.gz` / `.zip`).
- **D4 · OS link and file associations.**
  - Linux: the `.desktop` file declares `x-scheme-handler/magnet` and `application/x-bittorrent`. The desktop then offers Hyades as a handler without taking over an existing default.
  - Windows: no associations in v1.0. cargo-packager's NSIS template writes `HKCU\Software\Classes\magnet` unconditionally, which would silently take over qBittorrent and similar apps.
  - macOS: no associations in v1.0. macOS delivers opened links as Apple Events, which Slint/winit 0.30 do not surface, so a declared handler would launch Hyades and drop the link.
  - Both Windows and macOS go on the later list for 1.1. Until then the clipboard offer and paste cover them, and the browser extension (M8) adds more.
- **D5 · macOS ships one universal build.** Both architectures are built on the arm64 runner and joined with `lipo` into a single DMG and a single update asset.
- **D6 · Signing is optional per platform.**
  - Every signing step runs only when its secrets exist. Without them, the build still succeeds unsigned.
  - macOS without an Apple Developer ID is ad-hoc signed (`codesign -s -`).
  - Windows signing uses SignPath Foundation (free for open source) once the project is accepted.
  - The README explains the first-launch warnings for unsigned builds.
  - The update manifest is always signed. Its key is the user's own minisign key (Task 5), separate from OS code signing.
- **D7 · Updates are checked 30 s after launch, then every 24 h while running.**
  - The check is on by default and can be turned off in Advanced settings. The only request is a GET to GitHub; nothing is sent about the user.
  - Installable updates download in the background and wait for "Restart". Nothing installs without that click.
- **D8 · Linux packages are built on Ubuntu 22.04** (glibc 2.35), so the AppImage and the deb run on Debian 12, Ubuntu 22.04 and newer.
- **D9 · Parked, not in M7:**
  - proxy credentials in the keychain;
  - `0480p` normalisation;
  - listing audio ids that `--quality` refuses;
  - the empty temp folder after a crash;
  - yt-dlp `SHA2-256SUMS.sig` checking;
  - Windows legacy console colours;
  - the spec's "Later" list.
  - They go into `docs/LATER.md` (Task 13) so they are not lost.

## Global Constraints

- **MSRV:**
  - `rust-version = "1.89"` for the workspace crates, checked by CI's `msrv` job.
  - `apps/taurus-desktop` and the new `xtask` crate declare `1.92`. Both are excluded from the 1.89 check (`--exclude taurus-desktop --exclude xtask`).
- **License:** GPL-3.0-or-later. Any new dependency must be compatible with it: MIT, Apache-2.0, BSD, ISC, Zlib, MPL-2.0 or GPL.
- **No new C build dependencies** in the app or the engine. Packaging tools that run only in CI (NSIS, linuxdeploy, hdiutil, codesign) are fine.
- **Text in the window:**
  - Every user-visible string inside the window is `@tr(...)` in a `.slint` file.
  - Text the OS shows outside the window (tray, notifications, the start-up message box) comes from the `ShellText` global (Task 3).
  - Rust code never builds user sentences from pieces.
- **Plain language.** User copy follows the existing Simple-mode voice: short, plain, no engine terms. Every string this plan fixes is quoted exactly, and the implementer uses it verbatim.
- **Product name.** "Hyades" is never translated and never pseudo-localised: the pseudo-locale keeps the word `Hyades` as is.
- **Test hooks.**
  - Hooks that weaken checks stay debug-only, as in M5/M6: `TAURUS_FAST_TIMING`, `TAURUS_TORRENT_TEST_PEERS` and `TAURUS_TOOL_SOURCES`.
  - `HYADES_UPDATE_MANIFEST` (Task 6) works in release builds on purpose. It only changes where the manifest comes from: the signature check against the compiled-in key still applies.
- **Secrets.** Secrets never appear in the repo, in logs or in the conversation. Workflows read them from GitHub secrets. The private minisign key never enters the repository or CI logs.
- **Commits:**
  - Commit after every green step group, using conventional-commit subjects as in M6.
  - Before each push, run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`. All must be green.
  - CI on the three OSes must be green before Task 13's tag.

## Review Focus

1. **A failed automatic update check stays quiet.** This covers being offline, GitHub answering 403 or 5xx, and a captive portal returning HTML. No banner and no dialog appear; "Check now" says "Couldn't check for updates. Try again later." Tests: `captive_portal_page_is_refused` (Task 4) and `automatic_check_failure_is_quiet` (Task 6).
2. **A partial or tampered update file is never installed.** A `.part` file left by a crash, or a file whose size or hash differs from the signed manifest, is deleted and downloaded again. Tests: `stale_partial_is_discarded` and `download_checks_size_and_hash` (Task 4).
3. **An install the user cannot write to falls back to the website.** This covers an AppImage in a root-owned folder and an `.app` in a read-only `/Applications`. Nothing is left half-replaced, and the banner offers "Get it" instead. Tests: `unwritable_appimage_falls_back` and `bundle_swap_restores_old_on_failure` (Task 6).
4. **"Restart" during running downloads** quits through the normal engine shutdown before the new version starts, so downloads continue afterwards. Test: `restart_records_and_quits` (Task 6). The real-run check is in Task 13.
5. **Long translations never hide an action** at 420×640. Test: `pseudo_catalog_covers_every_string` (Task 2). The manual pass is Task 12.

- Produces in `po.rs`:
  - `struct Entry { ctxt: Option<String>, id: String, plural: Option<String> }`
  - `fn parse_pot(text: &str) -> Vec<Entry>`
  - `fn write_po(entries: &[Entry], lang: &str, translate: impl Fn(&str) -> String) -> String`
  - `fn pseudo(s: &str) -> String`
- Produces in `taurus_desktop::i18n`:
  - `pub fn choose(env: Option<&str>, setting: Option<&str>) -> Option<String>`. The env wins, then the setting; `None` means "leave it to the OS locale". Empty strings count as unset.
  - `pub fn apply(lang: Option<&str>)`. It calls `slint::select_bundled_translation`; when the language isn't bundled, it logs `hyades: no translation for <lang>` and keeps English.

**Catalog rules:**
- `en` holds empty `msgstr`s, so gettext falls back to the source text. Selecting `en` is how the app returns to English.
- `en_XA` is the pseudo-locale, with the header `Plural-Forms: nplurals=2; plural=(n != 1);`.
- `msgctxt` lines are kept exactly as extracted.

`pseudo(s)`, which the tests pin:
1. Placeholders pass through untouched: `{0}`…`{9}`, `{n}`, `{}`, `\n`, and the word `Hyades`.
2. In the rest, ASCII letters map to these accented forms:

   ```
   a→á e→é i→í o→ó u→ú y→ý c→ç n→ñ
   A→Á E→É I→Í O→Ó U→Ú Y→Ý C→Ç N→Ñ
   ```

   Other characters are unchanged.
3. The result is padded with `·` until its character count is at least 1.4 × the source's, rounded up.
4. The whole is wrapped as `⟦…⟧`.

### Task 4: Update check and download in the engine

**Files:**
- Create: `crates/taurus-core/src/update/mod.rs`, `update/manifest.rs`, `update/fetch.rs`, `update/tests.rs`
- Modify: `crates/taurus-core/src/lib.rs` (`pub mod update;`), `crates/taurus-core/Cargo.toml`
- Modify workspace deps: `minisign-verify = "0.3"`, `semver = "1"`, `minisign = "0.10"` (testkit and xtask only)
- Create: `crates/taurus-testkit/src/release.rs` (fake release host)

**Manifest format.** `latest.json` is signed as a whole. Its signature is `latest.json.minisig`, fetched from the same URL plus `.minisig`.

```json
{
  "version": "1.1.0",
  "pub_date": "2026-12-01T10:00:00Z",
  "notes": "Short release notes, plain text.",
  "page": "https://github.com/nikethai/taurus/releases/tag/v1.1.0",
  "platforms": {
    "windows-x86_64":         { "url": "https://…/Hyades_1.1.0_x64-setup.exe", "size": 12345678, "sha256": "<64 hex>" },
    "windows-aarch64":        { "url": "…_arm64-setup.exe", "size": 0, "sha256": "" },
    "macos-universal":        { "url": "…_universal.app.tar.gz", "size": 0, "sha256": "" },
    "linux-x86_64-appimage":  { "url": "…_x86_64.AppImage", "size": 0, "sha256": "" },
    "linux-aarch64-appimage": { "url": "…_aarch64.AppImage", "size": 0, "sha256": "" }
  }
}
```

**Interfaces:**
- Produces `taurus_core::update`:
  - `pub struct UpdateConfig { pub manifest_url: Url, pub public_key: String, pub platform: Option<String>, pub current: semver::Version }`. `public_key` is the minisign public key's base64 line.
  - `pub struct Manifest { pub version: semver::Version, pub pub_date: Option<String>, pub notes: String, pub page: Url, pub platforms: BTreeMap<String, Asset> }`. `version` accepts a leading `v`.
  - `pub struct Asset { pub url: Url, pub size: u64, pub sha256: String }`
  - `pub struct Release { pub version: semver::Version, pub notes: String, pub page: Url, pub asset: Option<Asset> }`
  - `pub enum UpdateError { Offline(String), BadSignature, BadManifest(String), Mismatch, Disk(String) }` (with `thiserror`)
  - `pub fn verify_manifest(json: &[u8], minisig: &str, public_key: &str) -> Result<Manifest, UpdateError>`
  - `pub fn platform_key(os: &str, arch: &str, appimage: bool) -> Option<String>`. The mappings are:
    - `("windows", a)` → `windows-{a}`;
    - `("macos", _)` → `macos-universal`;
    - `("linux", a)` with `appimage` → `linux-{a}-appimage`;
    - anything else → `None`.
  - `pub async fn check(client: &reqwest::Client, cfg: &UpdateConfig) -> Result<Option<Release>, UpdateError>`
  - `pub async fn download(client: &reqwest::Client, asset: &Asset, dir: &Path, progress: impl Fn(u64, u64) + Send) -> Result<PathBuf, UpdateError>`
- Consumes `network::build_client(&settings.network.proxy)` from callers, so the user's proxy applies.

**Rules:**
- **Manifest:** at most 1 MiB, and the signature file at most 4 KiB. Anything larger is `BadManifest`. The signature is verified before the JSON is parsed.
- **Which release is offered:**
  - `check` returns `None` when `manifest.version <= current`.
  - It also returns `None` when the manifest version is a prerelease and `current` is not.
  - Otherwise it returns `Some(Release)`, with `asset = platforms.get(platform)` (it may be `None`: notify-only).
- **Download target:**
  - The asset URL must be `https`, or `http` to a loopback host.
  - The size must be at most 500 MiB.
  - The file name is the URL's last path segment, which must be non-empty and contain no `..`.
- **Download process:**
  - Write to `dir/<name>.part` from scratch, deleting any existing `.part` first. Hash with SHA-256 while streaming.
  - If the size differs from `asset.size` or the hash differs → delete the `.part` and return `Mismatch`.
  - Otherwise rename to `dir/<name>` (replacing an older file) and return that path.
- **Error mapping:**
  - HTTP status ≥ 400 and connection errors → `Offline(<status or reason>)`.
  - An HTML body where JSON was expected fails signature verification → `BadSignature`.

**Detection rules (`detect`):**
- **Windows:** `WindowsInstaller` when `exe`'s folder contains `uninstall.exe` (cargo-packager's NSIS writes it).
- **macOS:** `MacBundle` when an ancestor of `exe` ends in `.app` and `exe` sits in its `Contents/MacOS/`.
- **Linux:** `AppImage` when `appimage_env` is set to an existing file.
- **Otherwise:** `NotifyOnly`. This covers deb, rpm, `cargo run` and portable copies.

**Apply rules:**
- **`WindowsInstaller`:** returns `RunInstaller(downloaded)`. `spawn` runs it as `<installer> /P /R`: passive, it closes the old app if it is still running, then relaunches.
- **`AppImage`:**
  1. If `path`'s folder is not writable (try creating `.<name>.hyades-test`, then remove it) → `NotWritable`.
  2. Copy `downloaded` to `<folder>/.<name>.new` and set mode `0o755`.
  3. Rename it over `path`, which is atomic, and return `Relaunch(path)`.
- **`MacBundle`:**
  1. If the bundle's parent is not writable → `NotWritable`.
  2. Untar (flate2 + tar) into `<parent>/.hyades-update-<pid>/`. It must contain `Hyades.app/Contents/MacOS/hyades`, else `Broken`.
  3. Rename the old bundle to `<parent>/.Hyades-old-<pid>.app`.
  4. Rename the new bundle to the old bundle's path. If this fails, rename the old one back and return `Broken`.
  5. Delete the old bundle and the temp folder (best effort).
  6. Return `Relaunch(app)`. `spawn` runs `open -n <app>`.
  - Write the swap as a path-only function `swap_bundle(app: &Path, new_app: &Path) -> Result<(), ApplyError>`, so it is tested on every OS.
- **`NotifyOnly`:** no apply. The flow never downloads.

**Flow rules:**
- **When checks run:** at launch plus 30 s, then every 24 h, only while `check_updates` is true. "Check now" always runs.
- **Automatic check results:**
  - An error → `Idle`. It is quiet, but logged once with `detail::warn`.
  - `None` → `Idle`.
  - `Some` with no asset, or kind `NotifyOnly` → `Available`.
  - `Some` with an asset → `Downloading`, then `Ready`.
- **Manual "Check now" results:**
  - An error → `CheckFailed`.
  - `None` → `UpToDate`.
- **Failures:**
  - A download error → `Idle` for an automatic check, `CheckFailed` for a manual one.
  - `apply` → `NotWritable` or `Broken` → `InstallFailed { page }`.
- **Download folder:** `<data_dir>/updates/`. At start, delete every file there except the newest. While downloading, the engine's settings proxy applies (`network::build_client`).
- **Restart:**
  - "Restart" calls `apply`, then on `Ok(r)` calls `App::restart_to_update(r)`. That stores `r` in `pending_restart` and calls `App::quit()` (the normal path: window hides, engine shuts down).
  - `main.rs` takes `pending_restart` after `rt.shutdown_timeout(...)`, which drops the single-instance listener, then calls `update_apply::spawn`. That ordering lets the new process become primary.
- **Manifest URL:** env `HYADES_UPDATE_MANIFEST` if set (any build), else `https://github.com/nikethai/taurus/releases/latest/download/latest.json`.
